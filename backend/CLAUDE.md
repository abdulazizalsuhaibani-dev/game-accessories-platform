# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ASP.NET Core 8 Web API for a game-accessories e-commerce store, backed by PostgreSQL via EF Core. It is the backend half of the platform; the React frontend lives in `../frontend` in this same repository and talks to this API over HTTP only. See the repo-root `CLAUDE.md` for the seams between the two halves.

All commands below assume you are in this `backend/` directory, not the repo root.

## Commands

```bash
dotnet build                       # 78 nullable warnings are the current baseline, 0 errors
dotnet run                         # http://localhost:5125, Swagger at /swagger
dotnet watch                       # hot reload
dotnet ef migrations add <Name>
dotnet ef database update
docker compose up --build          # container also listens on 5125
```

There is no test project and no linter configured. `dotnet format` is available from the SDK if you want consistent whitespace.

## Local setup a fresh clone needs

Two things are gitignored and must be regenerated by hand — a clean clone will not run without them:

- **`appsettings.json`** — holds `ConnectionStrings:Local` (Npgsql format, e.g. `Host=localhost;Port=5432;Database=ECommerceDb;Username=postgres;Password=...`) and the `Jwt` section (`Key`, `Issuer`, `Audience`). `appsettings.Development.json` is committed but only carries log levels.
- **`Migrations/`** — run `dotnet ef migrations add InitialCreate` then `dotnet ef database update`.

The API cannot mint an admin: registration hardcodes `UserRole.Customer` and the only promotion path (`PUT /api/v1/Users/{userId}/role`) is itself admin-only. Bootstrap the first admin by updating the row directly in Postgres.

## Architecture

Strict four-layer flow, one vertical slice per domain concept (User, Product, Category, SubCategory, Cart, Order, Payment, Coupon, Review):

```
Controller  → IXService / XService → XRepository → DatabaseContext (EF Core)
src/Controllers  src/Services/<domain>/  src/Repository/   src/Database/
```

- **Controllers** are thin: authorize, call the service, wrap in `Ok`/`Created`. They never touch a repository or the DbContext.
- **Services** hold all business rules and throw `CustomException` for anything the caller did wrong. They map entities ↔ DTOs with `IMapper`.
- **Repositories** are plain classes over `DbSet<T>`, registered as *concrete types* in DI (not behind interfaces) — services take `ProductRepository`, not `IProductRepository`. Only services get an interface.
- **DTOs** live in `src/DTO/<Domain>DTO.cs` as nested classes inside an outer wrapper class, so consumers write `using static src.DTO.ProductDTO;`.
- **Mapping** is one single `MapperProfile` (`src/Utils/MapperProfile.cs`) for every domain. Update DTOs go through `.ForAllMembers(opts => opts.Condition(...srcProperty != null))` so null fields mean "leave alone" rather than "clear".

### Wiring a new domain

Every piece is registered by hand in `src/Program.cs`. Adding an entity means: entity → `DbSet` on `DatabaseContext` → DTO file → `MapperProfile` entries → repository → `IXService`/`XService` → controller → **two `AddScoped` lines in `Program.cs`** (service-by-interface and repository-by-concrete-type). Forgetting the `Program.cs` line is the usual cause of a startup DI failure.

### Cross-cutting pieces

- **Errors**: `CustomException` (`src/Utils/CustomException.cs`) carries an HTTP status and has factories — `NotFound`, `BadRequest`, `UnAuthorized`, `Forbidden`, `InternalError`. `ErrorHandlerMiddleware` turns it into `{StatusCode, Message}` JSON. Any *other* exception is logged server-side and answered with a generic 500 — never surface internal detail by throwing a bare `Exception` with a user-facing message; use `CustomException`.
- **Auth**: JWT bearer. `TokenUtils` mints tokens with `NameIdentifier`, `Email` and `Role` claims, 1-day expiry. Endpoints use `[Authorize]` / `[Authorize(Roles = "Admin")]`. For resources a customer may only touch when they own them, call `AuthorizationUtils.EnsureOwnerOrAdmin(User, ownerId)` at the top of the action — the check belongs in the controller, before the service call.
- **CORS**: a named allowlist policy in `Program.cs` hardcodes `http://localhost:3000` and the deployed store origin. A new frontend origin requires editing that list.
- **Middleware order** (`Program.cs`): Logging → ErrorHandler → CORS → Authentication → Authorization → controllers. Swagger is registered only when `ASPNETCORE_ENVIRONMENT=Development`.

## Conventions and gotchas

- **Routes are PascalCase.** Every controller uses `[Route("api/v1/[controller]")]`, so the live paths are `/api/v1/Products`, `/api/v1/Users`, `/api/v1/Orders`, `/api/v1/Reviews` — matching the class name, not the lowercase paths in `README.md`. **The README's endpoint list is stale** (e.g. it documents `POST /api/v1/orders/checkout`; the real route is `POST /api/v1/Orders`). Read the controller, not the README. Note `ReviewController.cs` declares class `ReviewsController` → route `/api/v1/Reviews`.
- **`UserRole` is a real PostgreSQL enum**, not an int column. `Program.cs` builds an `NpgsqlDataSourceBuilder` and calls `.MapEnum<UserRole>()`, and `DatabaseContext.OnModelCreating` calls `HasPostgresEnum<UserRole>()`. Adding or renaming a role means touching both plus a migration.
- **`CartDetails.Subtotal` is computed inside the `Quantity` setter** from `Product.ProductPrice`. In an object initializer, `Product` must be assigned *before* `Quantity` or the subtotal silently lands at 0.
- **`GET /api/v1/Products` returns `{ products, productsCount }`, and `productsCount` is the total row count of the table** — it ignores the search/filter arguments. Do not use it as a filtered-result total for pagination.
- **`SearchProcess`** (`src/Utils/`) is the combined search + filter + sort + paginate query object bound with `[FromQuery]`; `ProductRepository.GetAllAsync` applies all four stages in that order. Defaults are `Limit=5`, `Offset=0`, `SortBy=price`. The older single-purpose `PaginationOptions`, `FilterationOptions` and `SortOptions` back the separate `/search`, `/filter` and `/sort` endpoints.
- **Order status is a magic string** validated against `OrdersController.orderStatuses` (`ordered`, `shipped`, `on delivery`, `delivered`), compared case-insensitively. New orders start as `"Ordered"` with `ShipDate = now + OrderService.deliveryDays`. Creating an order decrements `Product.SKU`; cancelling restores it, and cancellation is only allowed while the status is still `Ordered`.
- **`OrderService.CreateOneAsync` returns `null` for insufficient stock** rather than throwing, and the controller translates that into a 400. Preserve that contract if you touch it.
- **`Order.Address` is capped at 100 chars** on both the entity and `OrderCreateDTO`, and `[ApiController]` auto-validates the DTO — a longer address is rejected with a 400 before the service is reached. The store composes its address line from several fields, so this limit is easy to trip from the frontend.
- **Password rules** (length ≥ 8, one digit, one special char) are duplicated inline in both `CreateOneAsync` and `UpdateOneAsync` in `UserService`. Change both. On update, a null password means "unchanged" — the stored hash is copied into the DTO and deliberately *not* re-hashed.
- **Role can never be derived from user input.** Signup forces `Customer`, update copies the existing role, and `UpdateRoleAsync` refuses to demote the last remaining admin. Several past security fixes live in these paths (see comments) — keep them intact.
- **Nullable warnings**: the build emits ~78 CS86xx warnings today. They are pre-existing noise, not a regression signal, but don't add more in code you touch.
